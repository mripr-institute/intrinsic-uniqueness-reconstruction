# Audit guide

The mathematical paper, its Lean encoding, kernel typechecking, coverage
mapping and dependency auditing are separate kinds of evidence.

## Current authoritative files

| File | Role | Maintenance |
| --- | --- | --- |
| [lean-coverage.json](lean-coverage.json) | Named-statement ledger, statement hashes, source locations, tracked equations and supplementary scope assessment | Generated |
| [lean-coverage.md](lean-coverage.md) | Readable coverage and equation tables | Generated from the same ledger |
| [proved-inventory.md](proved-inventory.md) | Component mappings and distinct mapped-declaration count | Generated from the same ledger |
| [maps/core-closure.json](maps/core-closure.json) | Intrinsic/core and global reconstruction mappings | Maintained source map |

| [axiom-dependencies.md](axiom-dependencies.md) | Scope and readable verification summary | Generated from the same evidence |

Current totals are in the coverage ledger and inventory. Equations belonging
to named statements are not additional paper results. Global A/B and C/D are
paired labels of single theorem environments. Definitions are counted
separately from named results.

## What the checks mean

`rebuild_coverage.py` extracts named environments from the current LaTeX and
joins them to the maintained maps. It checks classifications, declaration
mapping presence and residual consistency, then generates the reports. With
`--lean`, it asks Lean to resolve every distinct mapped declaration through
the compiled `Sigma` umbrella. This is not an automated proof of semantic
equivalence between prose and formal statements; the maps record that review.
Their cumulative notes preserve authorship, earlier findings and subsequent
resolutions, rather than serving as current task lists.

`Verify.py` scans repository Lean source for admissions and project axiom
declarations, builds the library and runs the complete committed
`SigmaAxioms.lean` list. That list is not every declaration in Lean or mathlib.
Mathematical hypotheses remain parameters even when a declaration depends
only on the permitted foundational axioms.

Completion concerns the named results and tracked equations under their
supplied foundations. The [supplementary scope assessment](lean-coverage.md#scope-outside-the-named-statement-inventory)
retains separately unmapped proof-only combinatorial assertions. The
machine-readable `unproved_components` key means remaining **formalization**
components; it does not say that the paper lacks mathematical proofs.

## Regeneration

Run from the repository root:

```sh
python3 scripts/rebuild_coverage.py --write
python3 scripts/rebuild_coverage.py --check --lean --require-complete
python3 lean/Verify.py --write-report
python3 lean/Verify.py --check-report
python3 scripts/check_docs.py
```

Edit the maintained maps when a reviewed mapping changes. Do not hand-edit
generated reports. `--check` checks deterministic rendering, including the
root README coverage table. Verification timestamps change only when a new
full run is recorded; `--check-report` checks saved fingerprints and rendering
without rerunning Lean.

## Historical evidence

[history/](history/README.md) preserves reconstruction records, bounded reviews,
old maps, milestone axiom reports and provenance manifests. Earlier
partial/missing totals are historical evidence, not inputs to the current
coverage generator. Citations from current maps preserve review provenance;
they do not make old totals current.
